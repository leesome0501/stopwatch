# 증권사 9곳은 API로, 나머지는 엑셀로 채운다

2026년 10월 기준으로 조사 대상 25개 증권사 가운데 개인이 리눅스 서버에서 HTTP로 자기 계좌를 조회할 수 있는 공식 API는 **정식 서비스 6곳(한국투자, 키움, LS, NH투자, DB, 토스)**과 **베타이거나 반공식인 3곳(KB, 메리츠, 다올)**입니다. 대신·하나·신한·유안타·유진은 **32비트 Windows COM/OCX 방식만** 제공하고, 미래에셋·삼성·한화·교보·현대차·IBK·SK·신영·부국·상상인·카카오페이는 개인용 API를 찾지 못했습니다. 더 큰 걸림돌은 현금 원장입니다. 입출금·배당·이자·세금·환전을 한 API로 모두 돌려주는 곳은 **키움 REST `kt00015`(위탁종합거래내역)뿐**입니다. LS `CDPCQ04700`은 일부만 확인됐고, 한국투자는 배당(계좌 권리현황)과 해외 일별거래내역까지만 확인됐습니다. 나머지 API는 잔고·보유종목·체결에 머뭅니다. CODEF 같은 수집 대행은 개인에게 하루 100회 데모만 열려 있고, 마이데이터는 허가받은 사업자만 호출할 수 있습니다. 그래서 둘 다 주 경로가 될 수 없습니다. 따라서 AssetHub는 **"API는 매일의 잔고·체결 스냅샷, 엑셀은 과거 백필과 현금 원장"이라는 이중 구조**로 가야 합니다. 구현은 키움·한국투자 어댑터와 증권사별 엑셀 파서를 먼저 만들고, 토스·NH·LS·DB를 붙인 뒤, KB·메리츠·다올은 정식화를 기다리는 순서를 권장합니다. 가족 계좌는 구성원마다 **본인 명의 키와 본인 동의**로만 연결해야 합니다. 한 사람이 가족 전원의 인증서를 쥐는 구조는 법적·약관상 위험이 큽니다.

> **조사 한계:** 조사 환경에서 대부분의 증권사 사이트를 직접 열지 못했습니다(DNS 실패 또는 프록시 403). openapi.kiwoom.com, cybosplus.github.io, nhplug.com, blog.kbsec.com, securities.miraeasset.com, developers.tossinvest.com, developer.codef.io, hyphen.im 등이 여기에 해당합니다. 이 보고서에서 "스니펫"으로 표시한 항목은 검색엔진 발췌만으로 확인한 것입니다. **"미러"는 제3자가 GitHub에 복제한 공식 스펙입니다.** 두 종류 모두 구현 전에 각 증권사 공식 포털에서 다시 확인해야 합니다. 직접 읽은 1차 자료는 GitHub 저장소(한국투자·NH·DB·메리츠 공식 저장소 등)와 PyPI 메타데이터가 대부분입니다. "API 없음"은 찾지 못했다는 뜻이지, 없다는 확인이 아닙니다.

## 2026년 REST 물결로 서버에서 바로 붙는 증권사가 9곳이 됐다

2026년 여름 증권업계에 개인용 Open API 출시가 몰렸습니다. 8월 보도는 다올·KB·토스를 후발 주자로 꼽았습니다 ([시사저널e](https://www.sisajournal-e.com/news/articleView.html?idxno=422947), 스니펫). 다른 보도는 한국투자·KB·NH·토스·DB에 이어 메리츠도 참전했다고 정리했습니다 ([시사오늘](https://www.sisaon.co.kr/news/articleView.html?idxno=204260); [SBS Biz](https://biz.sbs.co.kr/article/20000339624), 스니펫). 반대로 별도 수수료 없이 서버·보안 비용만 늘고 API 키 유출이 계좌 위험으로 이어진다는 업계의 우려도 보도됐습니다 ([인베스트조선 2026-08-19](https://www.investchosun.com/site/data/html_dir/2026/08/19/2026081980116.html), 스니펫). 미출시 증권사가 주저하는 이유를 보여 주는 대목입니다.

표의 핵심은 세 그룹입니다. **첫째 그룹은 REST 그룹**입니다. 한국투자·키움·LS·NH·DB·토스가 정식이고, 메리츠·KB·다올이 조건부입니다. 이 그룹은 OS와 무관한 HTTPS라서 AssetHub 서버가 리눅스든 윈도우든 바로 호출할 수 있습니다. 한국투자 공식 예제는 Python 3.11 이상을 요구하고 Windows·macOS·Linux 설치법을 모두 안내합니다 ([공식 README](https://github.com/koreainvestment/open-trading-api)). DB 저장소도 Python 3.10 이상에서 세 OS 설치 절차를 제공하고, 대상 사용자로 "개인 투자자"를 명시합니다 ([DBsecurities/dbsec-open-api](https://github.com/DBsecurities/dbsec-open-api)). 메리츠는 OpenAPI 3.1 스펙(REST 71개)과 AsyncAPI 스펙(실시간 14개)을 공개했습니다. 다만 **아직 베타이고, 앱키 하나가 계좌 하나에 묶이며, 모의투자가 없습니다** ([meritz-securities/open-api](https://github.com/meritz-securities/open-api)).

**둘째 그룹은 Windows 전용 그룹**입니다. 대신 CYBOS Plus는 "32bit COM·윈도우 전용·크레온 HTS 필요"이고, HTS를 종료하면 API도 끊깁니다 ([algolab 2026](https://algolab.co.kr/blog/daeshin-ls-securities-algotrading-guide-2026), 제3자). 하나 1Q는 32비트 Python과 공동인증서를 요구합니다 ([GitHub K021/hana](https://github.com/K021/hana)). NH의 구 QV API는 Wine/Docker로 띄울 수는 있지만, Windows 이벤트 구동 방식이라 **화면 없는(headless) 환경에서는 제대로 동작하지 않습니다** ([qvopenapi-rs](https://github.com/bekker/qvopenapi-rs)). 따라서 AssetHub를 Windows 서버에 올리더라도 이 API들은 로그인된 데스크톱 세션이 있어야 합니다. "Windows 서버라서 COM도 된다"는 생각은 성립하지 않습니다.

**셋째 그룹은 API가 없는 그룹**입니다. 2026년 8~9월 업계 정리 기사들은 한화·교보·현대차·IBK·SK·신영·부국·상상인·우리투자를 언급하지 않습니다 ([뉴스투데이 2026-09-01](https://www.news2day.co.kr/article/20260901500312); [시사저널e](https://www.sisajournal-e.com/news/articleView.html?idxno=422947), 스니펫). 미래에셋 공식 페이지에서 확인되는 것은 고객의 전략 프로그램을 Kairos HTS에 잇는 "AnyLink"뿐입니다 ([미래에셋 imf401](https://securities.miraeasset.com/imf/200/imf401.do), 스니펫). 카카오페이증권은 REST API 계획을 묻는 개발자 질문에 공식 답변이 없었습니다 ([Kakao DevTalk](https://devtalk.kakao.com/t/api/122181), 스니펫).

## 신청 조건과 한도가 어댑터 설계를 좌우한다

REST 그룹 안에서도 운영 조건은 크게 다릅니다. 이 차이가 스케줄러, 토큰 캐시, 네트워크 설정을 결정합니다.

이 조건들에서 설계상 함의가 세 가지 나옵니다. 첫째, **키움은 고정 송신 IP가 필수**입니다. 가정용 유동 IP 서버라면 고정 IP 회선이나 VPN 출구를 마련해야 합니다. 또 매일 동기화하면 3개월 미접속 자동 해지를 자연스럽게 피할 수 있습니다. 둘째, **한국투자는 토큰을 발급할 때마다 알림톡이 가므로** 토큰을 DB나 파일에 캐시해 하루 한 번만 발급해야 합니다. 한국투자 이용 기간이 1년이고 3개월 이상 "무거래" 시 해지될 수 있다는 스니펫은 특히 조심해야 합니다. 여기서 "무거래"가 매매를 뜻한다면 조회만 하는 AssetHub는 해지 대상이 될 수 있습니다. 연 1회 재신청 알림을 설계에 넣고, 정확한 조건은 포털에서 확인해야 합니다. 셋째, **방화벽에서 8080·8443·9443 같은 비표준 포트를 열어야 합니다**.

비용은 어느 곳에서도 API 이용료를 찾지 못했습니다. NH는 API 주문 수수료를 국내 0.01%, 해외 0.09%로 우대합니다 ([농민신문](https://www.nongmin.com/article/20260810500525)). DB는 Open API 국내 수수료 0.01% 행사를 연말까지 진행합니다 ([뉴스핌 2026-09-08](https://www.newspim.com/news/view/20260908000926)). 메리츠는 이용료가 없다고 보도됐습니다 ([SBS Biz](https://biz.sbs.co.kr/article/20000339624), 스니펫). KB는 이용료와 매매 수수료를 따로 매길 수 있다고 밝혔습니다 ([KB증권 블로그](https://blog.kbsec.com/about/kb%EC%A6%9D%EA%B6%8C-open-api-%EC%82%AC%EC%9A%A9%EB%B2%95/), 스니펫). 과거 조회 기간은 **어느 API에서도 공식 상한을 확인하지 못한 공통 공백**입니다. 확실한 수치는 한국투자 HTS [7451] 화면의 최대 10년, 그리고 마이데이터 표준의 최근 5년뿐입니다. 장기 백필은 API보다 HTS 엑셀이 더 확실한 경로입니다.

계좌 유형에도 제약이 있습니다. 한국투자는 계좌번호 8자리와 상품코드 2자리(01, 19, 21, 22, 29 등)로 계좌를 바꿔 조회합니다. 퇴직연금(29) API는 주식·ETF·ETN만 다루고 펀드는 조회하지 못합니다. **DC 가입자 계좌(55)는 아예 지원하지 않습니다** ([공식 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/domestic_stock/domestic_stock_functions.py)). 키움은 계좌가 앱키에 귀속되므로 `ka00001`로 계좌 목록을 받습니다 ([미러 스펙](https://github.com/KKimj/Kiwoom-REST-API)). ISA·연금저축 지원을 명시한 증권사 문서는 하나도 찾지 못했습니다.

오픈소스 래퍼는 REST 쪽만 살아 있습니다. PyPI 기준(2026-10-19 조회)으로 키움 REST 래퍼 `kiwoom-client`는 2026-09-13에 186개 엔드포인트를 지원하는 버전을 올렸습니다. `pykiwoom-rest`는 2026-07, `kiwoom-restful`은 2026-05에 업로드됐습니다 ([PyPI kiwoom-client](https://pypi.org/project/kiwoom-client/); [pykiwoom-rest](https://pypi.org/project/pykiwoom-rest/); [kiwoom-restful](https://pypi.org/project/kiwoom-restful/)). 한국투자는 공식 예제 저장소가 가장 확실한 기준이고, `python-kis`는 2025-10 이후 릴리스가 없습니다 ([PyPI python-kis](https://pypi.org/project/python-kis/)). ## 현금 원장 공백: 입출금·배당을 통째로 주는 API는 키움뿐이다

자산관리 앱에서 잔고만큼 중요한 것은 **돈이 왜 움직였는가**입니다. 입금, 출금, 배당, 이자, 세금, 수수료, 환전이 여기에 해당합니다. 이 영역에서 API들의 지원 수준은 극단적으로 갈립니다.

**키움 `kt00015`가 압도적입니다.** 요청 파라미터 `tp`로 전체, 입출금, 입출고, 매매, 환전(F), 입출금+환전(M), 외화매수·매도(G/H)를 고를 수 있습니다. `gds_tp`로는 국내주식·수익증권·해외주식·금융상품을 고릅니다. 응답 행마다 적요명(`rmrk_nm`), 수수료(`cmsn`), 거래·농특세(`trde_agri_tax`), 소득·주민세(`incm_resi_tax`), 이자(`int_ls_usfe`), 환율(`trde_unit`), 외화 정산금액, 외국납부세액(`frgn_pay_txam`), 그리고 **거래 후 예수금잔고(`entra_remn`)**가 붙어 나옵니다 ([미러 스펙](https://github.com/KKimj/Kiwoom-REST-API)). 다만 금액은 부호가 붙은 15자리 0 채움 문자열이고, 정렬 파라미터가 추가될 때 호환성이 깨진 이력이 있습니다 ([KiwoomRestApi.Net](https://github.com/dongbin300/KiwoomRestApi.Net)). 그래서 응답 스키마 버전을 고정하는 방어 코드가 필요합니다.

**LS `CDPCQ04700`(계좌 거래내역)이 그다음입니다.** 요약 블록 OutBlock5에 입금(`MnyinAmt`), 출금(`MnyoutAmt`), 입고·출고, 매수·매도 수수료, 세금, 외화 정산금액 합계가 있습니다. 하지만 행 단위 상세(OutBlock3)의 필드는 확인하지 못했습니다 ([미러 카탈로그](https://github.com/xorrhks0216/LsApiHelper)). 배당 행과 세금 분리 여부는 실제 호출로 검증해야 합니다.

**한국투자는 세 조각을 이어 붙여야 합니다.** 매매는 `inquire-daily-ccld`에서, 배당·권리는 `period-rights`(`CTRGA011R`, HTS [7344] 권리유형별 현황)에서, 해외 일별거래내역은 `inquire-period-trans`(`CTOS4001R`)에서 받습니다 ([국내 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/domestic_stock/domestic_stock_functions.py); [해외 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/overseas_stock/overseas_stock_functions.py)). 그래도 **은행 이체에 해당하는 입출금 엔드포인트는 공식 예제에서 찾지 못했습니다.** `CTOS4001R`이 배당·환전·세금을 포함하는지도 응답 필드를 확인하지 못했습니다. NH·DB·토스·메리츠·다올·KB는 잔고·예수금·체결 수준까지만 확인됐습니다. DB SDK에도 "거래내역" 이름의 함수가 없습니다 ([DBsecurities/dbsec-open-api](https://github.com/DBsecurities/dbsec-open-api)). 대신은 금일·전일 체결(`CpTd5341`·`CpTd5342`)만 있습니다. 잔고 TR `CpTd6033`도 펀드·RP의 평가와 예수금 변동을 빼고 계산합니다 ([CpTd6033](https://cybosplus.github.io/cptrade_new_rtf_1_/cptd6033_.htm); [CpTd5341](https://cybosplus.github.io/cptrade_new_rtf_1_/cptd5341_.htm), 스니펫).

이 공백을 메우는 방법은 네 가지이고, 서로 보완 관계입니다. **첫째는 HTS·웹 엑셀 백필**입니다. 미래에셋 Kairos [0650]은 매매·입출금·입출고를 기간별로 한 화면에서 거래구분 필터로 조회합니다 ([Kairos 0650](https://securities.miraeasset.com/kairos/0650.htm), 스니펫). 삼성은 웹 거래내역에서 계좌와 기간을 고른 뒤 엑셀로 내려받습니다 ([삼성 도움말](https://www.samsungpop.com/help/bb003.html), 스니펫). KB HTS는 화면 데이터를 엑셀·CSV·HTML·TXT로 내보냅니다 ([KB help 1005.pdf](https://help2.kbsec.com/pdf/1005.pdf), 스니펫). 한국투자 [7451]은 최대 10년치를 조회하고 고객센터를 통한 이메일·우편 발송도 받습니다 ([7451](http://truefriend.com/pro_help/7451.html)). 다만 **증권사별 열 머리글, 인코딩(CP949와 UTF-8), 병합 셀, HTML을 `.xls` 확장자로 저장한 파일 여부는 하나도 확인하지 못했습니다.** 가족 구성원이 자기 계좌로 표본 파일을 내려받는 작업이 파서 개발의 선행 조건입니다. 일반론으로는 HTML 표를 `.xls`로 내려주는 시스템이 있으므로 ([SumProduct](https://sumproduct.com/blog/article/buggin-out-4-html-files-with-xls)), 확장자보다 파일 시그니처로 형식을 판별해야 합니다.

**둘째는 예수금 스냅샷 대사(reconciliation)**입니다. 매일 장 마감 후 예수금을 스냅샷으로 저장합니다(한국투자 `inquire-balance`·`intgr-margin`·`foreign-margin`, NH·DB·토스의 예수금 조회). 전일 대비 변동에서 그날 체결 정산액과 확인된 배당을 빼면, 남는 금액이 입금·출금·이자 후보입니다. 이 행은 "추정"으로 표시해 txn에 넣고, 나중에 엑셀이 들어오면 실제 행으로 대체합니다. 키움은 행마다 `entra_remn`이 있으므로 "직전 잔고 + 정산금액 = 이번 잔고" 연쇄를 검사해 **누락 행을 자동 탐지**할 수 있습니다. 이 검증은 키움 원장 품질을 보증하는 가장 싼 장치입니다(추론).

**셋째는 PDF 증명서**입니다. 토스증권은 앱의 설정 → 계좌관리 → 증명서 발급하기에서 거래내역서·잔고증명서·거래확인서를 PDF로 발급합니다 ([토스증권 FAQ](https://corp.tossinvest.com/ko/faq), 스니펫). 카카오페이증권은 앱 안에서 1·3·6·12개월 또는 지정 기간의 증권거래내역을 봅니다. PDF 출력은 저품질 출처에만 나옵니다 ([phongnhaexplorer](https://ko.phongnhaexplorer.com/ko/%EC%9D%80%ED%96%89/%EC%B9%B4%EC%B9%B4%EC%98%A4%ED%8E%98%EC%9D%B4%EC%A6%9D%EA%B6%8C%EC%97%90%EC%84%9C-%EB%82%B4-%EC%A6%9D%EA%B6%8C%EA%B1%B0%EB%9E%98-%EB%82%B4%EC%97%AD%EC%9D%84-%EC%96%B4%EB%96%BB%EA%B2%8C-%EC%A1%B0.html)). 증권사별 PDF 양식은 서로 호환되지 않으므로 ([imagetotable.ai](https://imagetotable.ai/ko/convert/investment-statement-to-excel)) 파서도 증권사별로 만들어야 합니다.

**넷째는 연 1회 해외주식 양도세 계산내역**입니다. NH·신한·메리츠 등은 5월에 양도세 계산내역을 카카오톡과 이메일로 보냅니다 ([taxtimes](https://www.taxtimes.co.kr/news/article.html?no=269378)). 연간 실현손익의 대조 기준으로 쓰기 좋습니다. 증권사 신고대행은 대개 자사 거래만 포함하므로, 여러 증권사를 쓰는 가족이라면 AssetHub의 합산 기능이 실제 가치가 됩니다 ([glasswallet](https://glasswallet.com/calculate/stock-capital-gains/declaration)).

## 수집 대행과 마이데이터는 개인 앱의 주 경로가 될 수 없다

API가 없는 증권사 11곳을 한 번에 해결해 줄 것 같은 채널이 수집 대행입니다. 결론부터 말하면 **보조 수단에 그칩니다**. CODEF(헥토데이터 계열)는 업무구분 "ST"(증권) 상품으로 "증권사 전계좌 API"를 제공합니다. 증권사마다 필수 파라미터가 달라 별도 스프레드시트로 관리합니다 ([CODEF 증권사 전계좌 API](https://developer.codef.io/products/stock/common/a/account), 스니펫). 인증은 공동인증서(loginType 0)나 ID/PW(1)로 한 번 등록해 connectedId를 받는 방식입니다. 인증서 비밀번호는 CODEF 공개키로 RSA 암호화해 보냅니다 ([connected-id 가이드](https://developer.codef.io/common-guide/connected-id/list), 스니펫). 결정적 제약은 이용 등급입니다. **개인은 하루 100회 데모만 쓸 수 있고, 무제한 정식 등급은 사업자 정보와 프로젝트 심사를 거쳐야 합니다** ([CODEF glossary](https://developer.codef.io/common-guide/glossary), 스니펫). 하루 100회면 가족 4명 × 증권사 5곳 × 엔드포인트 2~3개의 일일 배치는 들어갑니다. 하지만 데모 기간 제한이 아직 있다면 지속 채널이 못 됩니다. 문서상 범위도 잔고와 입출금에 그치고 매매 체결내역은 없습니다. 지원 증권사 목록 스프레드시트도 열람하지 못했습니다.

하이픈은 스크래핑 기반 "개인계좌 증권사 조회" 상품으로 계좌·거래내역·잔액을 내세웁니다 ([하이픈 상품](https://www.hyphen.im/product/), 스니펫). 쿠콘은 "국내 전 증권사 중계망"을 갖췄습니다 ([쿠콘 기업분석 2023](https://ssl.pstatic.net/imgstock/upload/research/company/1677732291550.pdf)). 하지만 두 곳 모두 기업 계약 중심이고 개인 가입 조건은 확인하지 못했습니다. 토스·카카오페이 같은 앱 전용 증권사는 스크래퍼가 의존하는 인증서 기반 웹 로그인이 없을 수 있어 대행 지원 여부가 더 불확실합니다(추론).

마이데이터는 데이터 범위로만 보면 이상적입니다. 금융투자 업권 표준 API는 계좌 목록, 기본정보, 거래내역, 상품정보(보유), 연금 추가정보를 다룹니다 ([금융투자 업권 API 규격](https://developers.mydatakorea.org/mdtb/apg/mac/bas/FSAG0402?id=4)). 거래내역은 **최근 5년**까지 제공합니다 ([표준 API 기본 규격](https://developers.mydatakorea.org/mdtb/apg/dgi/bas/FSAG0101)). 그러나 토큰은 허가받은 본인신용정보관리업자에게만 발급됩니다 ([인증규격](https://developers.mydatakorea.org/mdtb/apg/dgi/bas/FSAG0102)). 개인 개발자가 직접 호출하는 길은 없습니다. 2025-06-18 시작한 마이데이터 2.0은 동의 절차를 줄이고 정기 전송 주기를 고르게 했을 뿐, 소비자에게 원천 데이터를 내주지는 않습니다 ([금융위원회](https://fsc.go.kr/no010107/84785)). 우회로는 하나뿐입니다. 뱅크샐러드 가계부의 "파일로 받기"는 자산과 가계부를 엑셀로 내보냅니다. 하지만 **항상 요청일 기준 직전 1년으로 고정**이고, 종목별 증권 상세가 들어가는지는 확인하지 못했습니다 ([뱅크샐러드 고객센터 #207](https://help.banksalad.com/207), 스니펫). 토스증권 거래·배당이 토스 가계부에 반영되지 않는다는 사용자 일화도 있습니다 ([Threads](https://www.threads.com/@fin__wisdom__/post/DHgoaMVB2l9/)). 그래서 마이데이터 앱을 거치는 경로로는 원장 정확도를 기대하기 어렵습니다.

중장기 변수는 개인정보보호법상 **본인전송요구권**입니다. 2025-03-13 시행령으로 "본인전송"이 생겼습니다. 홈페이지에서 볼 수 있는 정보를 암호화 파일로 내려받는 방식입니다 ([대륜 뉴스레터](https://www.daeryunlaw.com/newsletter/news/158)). 전 분야 확대가 추진 중이지만 중소기업은 전송 의무에서 빠집니다 ([이투데이](https://www.etoday.co.kr/news/view/2498595)). 금융 분야는 신용정보법이 주로 규율하므로 증권사 적용 시점은 불명확합니다. 언젠가 각 증권사에 "내 데이터 내려받기" 버튼이 생기면 AssetHub의 엑셀 가져오기 경로가 그대로 수혜를 받습니다.

비공식 도구도 하나 짚어야 합니다. `tossinvest-cli`(Go, `tossctl`)는 Playwright로 토스 웹 세션을 확보한 뒤 내부 API로 계좌·체결을 JSON·CSV로 뽑습니다. 제작자 스스로 **약관 위반 가능성과 예고 없는 중단 가능성**을 밝히고 있습니다 ([GeekNews](https://news.hada.io/topic?id=27782)). 토스는 이제 공식 API가 있으므로 이 도구를 운영 경로로 쓸 이유가 없습니다.

## 가족 계좌는 각자의 키와 각자의 동의로만 연결한다

모든 증권사 API는 개인의 HTS ID나 고객번호에 묶입니다. 한국투자는 HTS ID에 연결된 계좌만 API를 쓸 수 있습니다 ([공식 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/domestic_stock/domestic_stock_functions.py)). NH는 고객번호당 APP KEY 1개입니다 ([nhplug.com](https://www.nhplug.com/howto-use), 스니펫). 메리츠는 앱키 하나가 계좌 하나에 귀속됩니다 ([meritz open-api](https://github.com/meritz-securities/open-api)). 따라서 **다른 고객의 계좌를 조회하는 공식 경로는 없고, 가족 구성원마다 본인이 직접 신청한 키 세트가 필요합니다**. 메리츠처럼 계좌별 키라면 한 사람 안에서도 키가 여러 개 생깁니다. NH의 `acct_type 02`(운영 주문대리인)는 위임 접근 장치로 보입니다. 다만 가족 조회에 쓸 수 있는지는 약관 확인 전까지 가정하지 않습니다 ([nhplug-sdk](https://github.com/PLUG-OpenAPI/nhplug-sdk)).

법적으로 **본인 계좌의 자동 조회를 금지하는 근거는 찾지 못했습니다.** 신용정보법의 스크래핑 금지는 마이데이터 사업자를 대상으로 합니다 ([ZDNet 2022-01-04](https://zdnet.co.kr/view/?no=20220104193433)). 위험은 가족의 접근매체를 다루는 순간 생깁니다. 공동인증서, 비밀번호, OTP가 여기에 해당합니다. 전자금융거래법은 접근매체의 양도·대여를 처벌합니다 ([법무법인 YK](https://www.yklawfirm-crime.co.kr/blog/detective/12590)). 대법원은 무상의 일시적 사용 허락은 "양도"가 아니라고 봤지만, 대가를 받는 대여는 따로 처벌된다고 판단했습니다 ([2011도16167](https://casenote.kr/%EB%8C%80%EB%B2%95%EC%9B%90/2011%EB%8F%8416167)). 증권사 약관이 제3자의 접근매체 사용을 막는 경우도 흔합니다(약관 원문은 확인하지 못함). 2026년 8월 개인정보보호위원회는 본인전송 맥락에서 **무단 스크래핑을 금지**하고 사전에 약속된 스크래핑만 한시 허용했습니다 ([블로터](https://www.bloter.net/news/articleView.html?idxno=663539)). 이 규제는 대리 수집 업체를 겨냥한 것이지만, 스크래핑 의존 경로가 줄어드는 방향을 보여 줍니다. 이 절은 법률 자문이 아니며, 확실한 판단은 변호사나 증권사 확인이 필요합니다.

AssetHub에 적용할 원칙은 다섯 가지입니다. 첫째, **성인 구성원은 각자 로그인해 자기 키를 등록하고, 등록 시점에 동의 기록을 남깁니다.** 미성년자나 동의하지 않은 친척의 자격증명은 저장하지 않습니다. 둘째, **키와 시크릿은 DB 밖의 키로 암호화**합니다. 예를 들어 OS 키링, SOPS/age, 또는 Argon2id로 파생한 키와 AES-GCM을 씁니다. 한국투자도 토큰 파일을 남이 찾기 어려운 곳에 두라고 권고합니다 ([kis_auth.py](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/kis_auth.py)). 셋째, **어댑터는 조회 전용으로 만들고 주문 엔드포인트는 코드에서 빼 버립니다.** 메리츠처럼 읽기 전용 모드가 있으면 켭니다. API 키 유출이 곧 계좌 위험이라는 업계 우려가 현실적인 이유입니다 ([인베스트조선](https://www.investchosun.com/site/data/html_dir/2026/08/19/2026081980116.html), 스니펫). 넷째, 서버는 LAN이나 VPN 안에 두고 모든 자격증명 사용을 감사 로그로 남깁니다. 다섯째, 공동인증서를 요구하는 스크래핑은 AssetHub가 인증서를 보관하지 않는 구조일 때만 고려합니다. CODEF처럼 등록 후 connectedId만 쓰는 방식이 그 예입니다.

## AssetHub는 키움·한국투자 어댑터와 엑셀 파서부터 만든다

우선순위는 **"가족 자산이 그 증권사에 얼마나 있는가 × API 성숙도 × 현금 원장 커버리지"**로 정해야 합니다. 아래 순서는 가족의 증권사 분포를 모르는 상태의 기본값입니다. 실제로는 1단계에 들어가기 전에 가족 계좌 목록부터 만들어야 합니다.

| 순위 | 증권사 | 권장 방법 | 이유 |
|---|---|---|---|
| 1 | 키움 | REST: `kt00015`(원장) + `kt00018`(잔고) + `kt00004` | 유일하게 입출금·배당·세금·환전 원장을 API로 받을 수 있음 |
| 2 | 한국투자 | REST: 잔고·일별체결·`CTRGA011R`·해외 `CTOS4001R` + [7451] 엑셀 백필 | 공식 예제가 가장 성숙하고 해외까지 넓음. 입출금은 대사로 보완 |
| 3 | 엑셀 공통 | 기존 엑셀 가져오기를 증권사별 파서 플러그인으로 확장 | API가 없는 11곳과 대신·하나·신한·유안타·유진, 그리고 모든 증권사의 과거 백필을 한 번에 해결 |
| 4 | 토스 | REST (Account·Asset·Order History) + 거래내역서 PDF | 공식 GA, 국내·미국 통합. 스펙 변동에 대비해 버전 고정 |
| 5 | NH투자 | PLUG REST (공식 `nhplug` SDK) | 고객번호당 키 1개로 전 계좌. 원장은 엑셀 |
| 6 | LS | REST `CDPCQ04700` + `t0424` + 해외 `COSOQ00201` | 원장 일부 지원. 1 TPS 제약 |
| 7 | DB | REST 잔고·체결·해외 | 원장 없음. 스냅샷 용도 |
| 8 | KB, 메리츠, 다올 | 정식 출시나 공식 문서화 이후 어댑터 | 베타·반공식이라 스펙 변동 위험 |
| 보류 | 대신 등 COM 계열 | 필요할 때만 Windows 데스크톱 수집 에이전트 | HTS 상시 실행과 32비트 의존. 엑셀이 더 쌉니다 |

이 순서를 실행 단계로 풀면 다음과 같습니다.

| 단계 | 범위 | 핵심 산출물 | 완료 기준 |
|---|---|---|---|
| 0. 기반 (1–2주) | txn 스키마 확장, 거래종류 매핑 테이블, 자격증명 금고, 구성원별 동의 기록, 가족 전원의 표본 파일 수집 | `source`(api/excel/pdf/inferred), `external_id`, `confidence`, `balance_after`, `raw`(JSONB) 컬럼. (broker, account, date, external_id) 유일 제약 | 모든 가족 계좌의 표본 엑셀이 저장소에 있음 |
| 1. 핵심 API | 키움·한국투자 어댑터(조회 전용), 일일 잔고 스냅샷 테이블, 장 마감 후 배치 스케줄러, 토큰 캐시, 레이트리밋 | 키움 `kt00015` → txn 매핑, 한국투자 체결·권리 → txn | 키움 `entra_remn` 연쇄 검증 통과, 한국투자 토큰 하루 1회 발급 |
| 2. 엑셀 파서 | 가족이 실제 쓰는 무-API 증권사 + 한국투자 [7451] 장기 백필 | 증권사별 파서(파일 시그니처로 xlsx/HTML-xls/CSV 판별, CP949·UTF-8 처리) | 엑셀 행과 API 행이 `external_id`나 (일자, 금액, 종목)으로 중복 제거됨 |
| 3. 확장 API와 대사 | 토스·NH·LS·DB 어댑터, 예수금 대사 작업 | 잔차 기반 `inferred` 입출금 행, 대사 실패 알림 | 월말 예수금이 txn 누적과 일치하거나 차이가 표시됨 |
| 4. 조건부 | KB·메리츠·다올 정식화 대응, CODEF 데모 파일럿, 토스 PDF 파서, 5월 양도세 계산내역 대조, 필요 시 Windows 수집 에이전트 | 증권사별 기능 플래그 | 각 조건 충족 시 개별 착수 |

키움 원장을 표준 txn에 매핑하는 예는 아래와 같습니다. 다른 증권사 파서도 이 표를 기준으로 맞추면 됩니다.

| `kt00015` 필드 | txn 컬럼 | 비고 |
|---|---|---|
| `trde_dt`, `trde_no`, `orig_deal_no` | `trade_date`, `external_id`, `parent_external_id` | 멱등 키 |
| `rmrk_nm`, `trde_kind_nm`, `io_tp_nm` | `kind` (매핑 테이블 경유) | BUY/SELL/DEPOSIT/WITHDRAWAL/DIVIDEND/INTEREST/FEE/TAX/FX/TRANSFER_IN/TRANSFER_OUT |
| `stk_cd`, `isin_cd`, `stk_nm` | `symbol`, `isin`, `name` | |
| `trde_amt`, `exct_amt` | `gross_amount`, `net_amount` | 부호가 붙은 15자리 문자열을 Decimal로 변환 |
| `cmsn`, `trde_agri_tax` + `incm_resi_tax`, `int_ls_usfe` | `fee`, `tax`, `interest` | 세금은 항목별 원본을 `raw`에 보존 |
| `crnc_cd`, `trde_unit`, `fc_exct_amt`, `frgn_pay_txam` | `currency`, `fx_rate`, `fx_amount`, `foreign_tax_withheld` | 해외 배당 원천징수 추적 |
| `entra_remn`, `fc_entra` | `balance_after` | 누락 탐지용 잔고 연쇄 |

인프라 측면에서 두 가지를 챙겨야 합니다. 첫째, 리눅스 서버가 REST 그룹 전부를 소화합니다. 다만 아웃바운드 방화벽에서 8080(LS), 8443(NH·DB), 9443(메리츠)을 열어야 하고, 키움용 고정 송신 IP가 있어야 합니다. 둘째, 한국투자의 3개월 이전 체결 TR은 DB 부하 때문에 **15:30 이후, 짧은 기간 단위로 조회하라는 권고**가 있습니다 ([공식 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/domestic_stock/domestic_stock_functions.py)). 백필 작업은 야간에 기간을 잘게 쪼개 돌려야 합니다. Windows 에이전트는 대신 등에 가족 자산이 크게 묶여 있을 때만 검토합니다. 그 경우에도 HTS가 로그인된 데스크톱에서 돌면서 JSON을 FastAPI 수집 엔드포인트로 밀어 넣는 구조여야 합니다. 대신 API는 금일·전일 체결만 주므로, 에이전트를 만들어도 과거 이력은 결국 엑셀로 채워야 합니다.

## Conclusion

이번 조사에서 가장 중요한 발견은 2026년 개인용 Open API 확산이 **잔고·주문 위주의 확산**이었다는 점입니다. 증권사들은 AI 자동매매와 MCP 연동을 앞세워 API를 열었습니다. 하지만 자산관리 앱에 정작 필요한 입출금·배당·세금 원장을 제대로 주는 곳은 아직 키움 한 곳뿐입니다. 그래서 AssetHub의 진짜 핵심 자산은 API 어댑터 개수가 아니라 **증권사별 거래종류 문자열을 표준 txn으로 바꾸는 매핑 테이블과 잔고 연쇄 대사 로직**입니다. 이 둘은 API, 엑셀, PDF, 미래의 본인전송 파일이 모두 공유하는 계층이므로, 처음부터 데이터 출처와 독립적으로 설계할 가치가 있습니다.

남은 불확실성도 분명합니다. KB·메리츠의 정식 출시, 토스 Account 카테고리의 실제 엔드포인트, 한국투자에 숨은 원장 TR이 있는지가 그렇습니다. 이 셋 중 하나만 확인돼도 엑셀 의존도가 크게 줄어듭니다. 따라서 이 보고서의 표는 고정 결론이 아니라 **분기마다 각 공식 포털에서 갱신할 체크리스트**로 쓰는 것이 맞습니다. 특히 "스니펫"과 "미러"로 표시한 항목은 구현 착수 전에 반드시 원문으로 확인해야 합니다.
